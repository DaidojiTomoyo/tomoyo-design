## 实际实现依据

读取 `features/home/motion/` 下的 `controller.ts`、`resource-readiness.ts`、`resource-barrier.ts`、`motion-shell.tsx`、`opening.ts`、`page-entry.ts` 和 `opening.css`，并对照 `content/motion-studies.ts`、`lib/navigation/locale-navigation.ts`、`app/[locale]/layout.tsx`。采用边界以 `.impeccable/surfaces/app-page-tsx.md` 的「真实资源加载修正」为准，静态视觉继续继承已批准图稿。

服务端初始阶段为 `checking`，正文暂时隐藏，加载层也不立即显示。CSS 以 250ms 为显示延迟；控制器检查资源时使用 `loading`。正式首页在资源结算后检查加载层是否已经出现：未出现则直接 `complete`，不执行页面入场；已经出现则接续剩余字标形成并平滑退场，不再增加固定展示停留。是否显示加载由当次资源和已显示状态决定，与访问次数无关。

资源任务包含当前字体、页面中的首屏海岸图及海岸预览图，以及由实际 CSS 纹理 URL 创建的纸纹和蓝纹图片解码。布局预加载同一批优化纹理，检查字体错误和图片有效宽度。结果区分 `ready`、`degraded`、`timeout`、`aborted`；10 秒是资源故障上限，不是强制播放时间。失败、超时允许释放页面，取消则不再把旧结果写回。

首页不再使用播放记录，也没有旧的“再次访问”短入场规则。语言切换意图存于当前页面内存，刷新时重置，避免刷新被误判为语言切换。预览和显式重播仍展示完整编排，资源结算、字标形成后保留 650ms；只有这类演示具有固定展示停留。

6 秒 CSS 恢复只作用于未接管的 `checking`：恢复正文和滚动、隐藏加载层。已接管的 `loading` 不使用该提前结束路径，而由真实资源结果和 10 秒故障上限管理。迟到接管检查正文是否已被恢复为可见，避免再次覆盖。无脚本和减少动态效果的静态降级路径保留。

### 后台等待与滚动恢复边界复核

审查修正后的 `controller.ts` 不再因初始 `document.hidden` 退出正常资源检查。隐藏事件先检查 `motionPhase === 'loading'` 且资源状态仍为 `pending`，此时保留资源等待；资源结算后若页面仍隐藏，标记 `loadingUi="background"` 并直接完成，不播放装饰退场。资源已结算时切到后台仍可取消剩余装饰。`DESIGN.md` 已据此删除“隐藏标签页结束等待”的旧表述，并将平滑退场限定在前台路径。

`opening.css` 中减少动态效果和 `scripting: none` 两处滚动恢复选择器均为 `html:has(.motion-study[data-motion-phase])`，与加载滚动锁具有相同特异性，位于其后，可覆盖锁定规则。本次仅核对这两处源码，没有新增浏览器结论。

sidecar 未包含该过时的后台生命周期声明，无需修改；所有现有 token、组件片段及 `.impeccable/design.json` 整体保持不变。本次追加只修改 `DESIGN.md` 与本记录。
