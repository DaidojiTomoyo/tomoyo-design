# React Bits 分类目录观察

观察日期：2026-10-28。用户明确提供参考后，实际浏览了目录、动画分类、Animated Content 详情，以及手机导航。

## 浏览范围

- [全部组件](https://reactbits.dev/get-started/index)：桌面左侧保留分类导航和按组排列的效果名称；右侧是搜索、分类选择、排序与预览网格。
- [Animations 分类](https://reactbits.dev/c/animations)：点击分类后切换到独立分类 URL，右侧标题和网格随之变化，侧栏保留对应分类的条目。
- [Animated Content](https://reactbits.dev/c/animations/animated-content)：点击侧栏条目直接进入详情，侧栏滚动到当前条目并标明选中状态。右侧有 Preview / Code、设备尺寸、分享、Copy for AI；大画布下方有 Customize、Props 等内容。
- 390×844 手机详情：侧栏收进 Menu，打开后以纵向列表呈现分类和效果名称，顶部保留导航筛选。

当前站点展示的五个内容分类为 Text Animations、Animations、Components、Micro、Backgrounds。以上是本次浏览看到的内容，不将它们写为 Tomoyo 已有分类或已实现功能。

观察到搜索、排序、收藏与 Copy for AI 的入口；本次没有执行复制、收藏或检查源码，不宣称验证过这些功能的内部行为。

## 对 Tomoyo 的直接启发

1. 分类是持续可见的导航结构。目录、分类结果和效果详情共用一个框架，切换效果不必反复返回目录。
2. 网格负责按画面挑选，分组名称列表负责按目标查找；两者互补。
3. 分类拥有可直接访问的页面。搜索是横跨分类的查找方式，不能替代分类。
4. 详情让预览占主要空间，工具围绕当前效果排列。Tomoyo 把参数、提示词语言与复制放在预览附近，当前配置与输出描述必须一致。
5. 手机使用同一份分类树，入口明确；不要把桌面长侧栏硬挤进首屏。

React Bits 已经提供 Copy for AI，因此“有 AI 复制按钮”不应被当成独有能力。Tomoyo 的实现仍应围绕已确认任务：用户看懂效果、调整参数，将准确描述交给自己的 AI，并沿用自己的技术栈和设计。

## 本轮不直接沿用的部分

- 分类名称结合本项目词汇手册确定，覆盖动画、风格、材质、布局与配色。
- 颜色和字体继续使用 `DESIGN.md`；本轮用户指定的是分类浏览参考，没有要求替换现有视觉语言。
- 不引入付费推广、安装命令、依赖列表或完整组件 API 表作为第一版主结构。
- 分类、数量和可用状态来自实际内容，空分类不提前占据正式导航。
