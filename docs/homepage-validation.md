## 2026-10-27 开场节奏修正

用户反馈开场过短。检查发现资源缓存命中时，退场会在约 280ms 开始，早于逐字排版和海岸显影结束。本轮把资源准备与开场编排分开：先完整呈现字标或海岸，停留 650ms，再进入首页。资源已就绪时的编排总长分别为套色印刷 2290ms、活字排版 2370ms、海岸显影 2550ms。跳过时同时取消动画、结束准备阶段的等待；退场开始即释放旧的透明度填充帧。

本轮在 1280×720 桌面视口和 390×844 手机视口验证三种方案。六张 `*-held-*.png` 刻意截取完整呈现后的停留阶段，已逐一打开，不能拿来判断首页的静止布局。逐帧样式观察记录到约 647ms、656ms、654ms 的完整停留，最后遮片透明度均为 0。采样起点在自动点击结束之后，完整编排时长以上述配置计算为准，不将采样区间冒充精确的事件总时长。

三种手机预览的跳过结果均为完成状态、透明度 0、横向溢出 0。连续重播后通过键盘选择玻璃，焦点与所选效果正确；切换到英文后保持效果，开场没有重新播放。准备提示由真实资源状态驱动，已就绪时在停留期间显示“打开预览”。减少动态效果和慢资源路径以源代码核对为限，未新增真机性能结论。

## 2026-10-27 加载开屏与代码职责拆分

本节取代上文关于“跳过开场”和输入中断的现行规则；旧记录仅保留当时的验证事实。用户确认开场兼作加载开屏，本轮删除首页及预览的跳过按钮，以及点击、键盘、触屏、滚动的跳过监听。

首帧问题来自遮片的初始透明状态：原实现要等 React 接管后才显示。本轮在服务端输出 `loading` 状态，让 CSS 先显示遮片、排入字标并隐藏正文；控制器接续已有动画。资源准备与形成编排结束后自动入场，保留字标完整呈现后停留 650ms 的节奏。

### 实测结果

- `pnpm check`（ESLint、Prettier、TypeScript）和 `pnpm build` 通过；生产构建生成中英文首页及六个预览页，无新依赖。
- 在生产构建前设置本机测试代理，仅延迟 JavaScript 请求，HTML/CSS 不做改写。延迟 4 秒时，尚无接管标记，`phase=loading`、遮片 `opacity=1/visibility=visible`、正文 `visibility=hidden`，没有先露出首页。
- 将脚本延迟到 9 秒，观察到 CSS 在 6 秒恢复路径使正文可见、遮片隐藏、滚动恢复，此时仍无接管标记。脚本随后接管，状态直接完成，遮片保持隐藏。测试服务仅供本轮本机验证，不加入应用部署。
- 手机预览重播活字开屏后，点击画面并按 Escape，阶段仍为 `opening`，遮片可见。未出现“跳过开场”按钮。套色印刷、活字排版、海岸显影均可正常结束和切换。
- 磨砂玻璃选择与复制成功，实际剪贴板包含中文玻璃提示词及 `blur(18px)`。切换英文界面后仍保留玻璃和中文提示词，阶段标记为 `language`，未重播开屏；提示词语言可以另行改为英文。
