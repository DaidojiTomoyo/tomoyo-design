# 分类导航与参数切换动效修正

2026-10-28。用户反馈侧栏切页闪烁、导航与参数选项变化生硬，要求改善连续性与表现力。范围为既有 Operate 页面，不重新选择布局或视觉身份。

## 原因与动效安排

浏览器复现确认，详情之间导航时，侧栏的公共祖先被 `PageTransition` 降到 opacity 0.65。侧栏并未重新加载，却随整页淡入一起变亮，造成闪烁感。

- 焦点动作：侧栏使用一块连续移动的选中底板；参数预设与单选组的深蓝底板从当前裁切矩形滑移到目标，仅保留起止两个关键帧，整段使用 `cubic-bezier(0.2, 0.8, 0.2, 1)`。浅色标签随实际底板裁切，保持中途文字可读。
- 连续性：目录内部切页不再对根容器淡入。侧栏与顶部导航保持不动，右侧标题、效果画布及参数区按目录顺序横向衔接；只有这些局部节点参与，手机固定复制栏不进入位移祖先。
- 反馈：选中值立即生效，动画不阻挡链接和控件。快速改选采样当前画面并取消旧动画；自定义参数未命中预设时，参数底板收拢退出。
- 预算：侧栏单个装饰节点最多 360ms；内容最多三个节点、延迟总计不超过 50ms；单选组裁切局限于一个小控件，选中 240ms，退出 180ms，两者使用同一整段缓动。无新增运行依赖、栅格素材或循环动画。

保留中英文、原生链接与 radio、键盘焦点、分享参数、查询状态、原首页资源加载规则。初次挂载默认内容可见，首次选中状态不播放进场；减少动态效果和后台状态直接落实当前值，卸载清理动画与观察器。

## 单选切换卡顿修正（2026-10-28 追加）

用户继续反馈“调整效果”的选项切换卡顿。原实现把 300ms 动画拆为三个关键帧，中间帧位于 58% 时间点，即 174ms，并在两段分别应用缓动。第一段在中间帧减速停住，下一段再加速；这一速度变化会让一次滑移看起来分成两次运动。上一轮仅确认存在中间帧和快速改选接续，未检验整条路径的速度连续性。

本次将选中滑移改为 240ms、起止两个关键帧，整条路径只应用一次 `cubic-bezier(0.2, 0.8, 0.2, 1)`；移除中段伸展和圆角变化。未命中预设时仍以 180ms 收拢退出，并使用相同缓动。快速改选仍先读取当前可见裁切，再取消旧动画；减少动态效果、后台结算、尺寸变化与卸载清理沿用现有逻辑。

### 本次验证

- `pnpm check`、`pnpm build` 通过；`pnpm test` 为 35 / 35。新增 8 项测试加载实际 `useChoiceMotion`，验证整体缓动、当前可见帧接续、自定义收拢、无变化不重启、尺寸变化、减少动态效果、后台及卸载清理。DOM、React hook 生命周期和 WAAPI 在这些单元测试中使用模拟对象。
- 缓动公式按 100px 位移计算：旧路径在 174ms 前后速度从 0 跳至约 1.389px/ms；新路径在 174ms、180ms 的速度分别约为 0.0405、0.0349px/ms，持续减速。这是时间曲线计算，不是帧率测量。
- 同一浏览器通过原生点击，对修复前的 3004 服务和修复后的 3005 生产服务分别采样 48 次实时 `clip-path`。修复前可见接近中间位置后再次快速移动；修复后只有一段连续趋向目标的轨迹。原始采样与覆盖说明见 [choice-stutter-evidence.json](../.impeccable/review/catalog-motion/choice-stutter-evidence.json)。采样时刻来自自动化端，重复样式值不直接等同于掉帧。
- 实际操作覆盖连续往返点击预设、方向 radio 键盘切换、改为自定义参数、重置、切换英文和手机端缓动选项。1280px 桌面和 390px 手机视口均无横向溢出；浏览器 warning/error 为空。
- 已打开确认 [中文桌面控件](../.impeccable/review/catalog-motion/choice-fixed-desktop.png) 和 [英文手机控件](../.impeccable/review/catalog-motion/choice-fixed-mobile.png)。截图仅记录布局、选中与焦点状态，不证明整段动效帧率。

本次没有 GPU 性能追踪、真实手机或跨浏览器帧率数据；减少动态效果和后台行为由自动测试覆盖，未进行对应浏览器环境仿真。修复范围限定为已确定的缓动折点，未改动预览重播、URL 状态或页面布局。
